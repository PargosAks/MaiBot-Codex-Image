# 保留已有计划的等待恢复

插件 0.9.1 支持修复一种明确的停滞：错误的验收提示使模型对已有计划选择长时间等待，停止验收后原计划仍为 `planned`。恢复不新建作品、不更换空间、不清除操作、发送记录或已消耗额度；自主创作仍默认关闭。

## 正常调度

缩短 `idle_seconds` 后，原先过远的 `next_due` 会收敛到当前时刻加新间隔。后续 tick 不会不断延后该期限。此变更只调整空闲调度，模型明确设置的等待、失败退避和作品 `next_check_at` 继续生效。

连接轮询、绘图等待、Host tick 和模型超时的浮点配置使用浮点默认值，避免 Host 配置版本升级按默认值类型回填时丢失已有的浮点设置。默认时长本身不变。

“没有新聊天便等待”应只约束尚未选题的状态。已有作品无需收到第二条聊天才能继续创作、看图评审或分享；模型仍可因具体阻碍选择等待或放弃。提示词不构成越过授权、预算或发送锁的依据。

## 管理员离线恢复

`ArtistStore.restore_planned_wait(...)` 是可信维护接口，不暴露为模型工具或聊天命令。调用前必须停止该插件的 Host worker、取得同一 `RuntimeLease`，并保存数据库备份。只设置 `offline=True` 不能代替真正持有锁。

接口要求明确的 `space_id`、可信 `scope`、`expected_auth_version`、原 `work_id`、`last_wait_request_id`、唯一 `event_id` 及 `reason`。它在事务中验证：

- 当前委托已撤销，授权代次与预期一致；上一代授权及本代撤销记录完整。
- 没有活动 claim、持有中或结果未知的操作；原作品仍为未延期的 `planned`，没有待完成绘图。
- 最后一次已完成 claim 和最新成功思考能证明该作品的显式 `wait`；思考输入中的原计划与当前 brief 一致，当前退避仍对应那次等待。

通过后仅解除这次已确认等待、重新设置调度时间，并持久化一个带审计证据的内部 `idle` 唤醒。它不是聊天消息或绘图完成回执，也不会授予权限。相同键、相同内容再次调用不会再次清除新的退避；授权、作品或历史内容变化会被拒绝。

重新启用仍需新的明确委托。原操作保留原授权代次，新操作使用新代次；消费记录继续累计。维护工具不得将旧操作改写成新授权，也不得删除历史记录来通过启动检查。每日预算本身不是跨日验收总量限制；有明确总次数的验收应另设包含历史记录的累计守卫，并在跨日时停止。

## 本轮 VPS 验收边界

恢复沿用原空间、原作品和原 MCP 状态。历史三次成功思考纳入累计上限，绘图总量最多一次原图、一次细化、一次分享。守卫核对完整历史快照、新授权和原作品归属；MCP 验收入口也核对当前授权和实际插件操作。完成分享、异常、超时或跨日后关闭自主创作，并移除本次临时网络规则。

模拟测试、独立审查、VPS 后台记录与用户确认收图分别记录。模拟恢复通过不代表真实绘图成功；后台发送确认也不代替用户确认图片可见。
