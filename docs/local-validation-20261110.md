# 0.13.0 本地部署功能验证

## 环境与边界

本轮使用实际已安装的 **MaiBot 1.3.15、Dashboard 1.9.9、SDK 2.17.0、Python 3.14.7**，从发行 ZIP 解压到全新隔离实例。Host、worker、Runner、配置热更新、命令、聊天事件、定时调度、MCP HTTP 和 WebUI WebSocket 均实际运行。模型决策、视觉评审和 Codex 出图由本地替身提供；发送落到本地私聊或虚拟群 WebSocket，没有调用真实 Codex、付费图像 API 或 QQ。

实例与证据根为工作区下 `local-maibot/refactor-validation-20261110/`；使用 127.0.0.1 的 18039、18791、18792 三个端口。原有本地实例、生产任务、图片、额度和凭据不参与测试。没有提交、推送或部署 VPS，也没有替换 MCP。

首轮包 SHA-256 为 `530b166fb9759d9eedac0496a52ac653d66ce51beeb442dd1b4b515a165f2711`。浏览器发现并修复窄屏问题后的候选为 `1e2adc8f0da52262f948aa28e8ca6a0a9ae13fdf664ab9352e1ec95a3a27095a`；两个包均有 79 个文件，45 个生产 Python 文件逐字节相同，唯一变化是 `assets/studio.html` 的换行规则及中文注释。其后文档整理单独记录为发行元数据变化，不回溯声称首轮运行了新文档包。

## 数据保留、测试和审查

- 首次冷启动保留已完成的私聊作品，没有新模型或绘图调用。随后经公开 `/api/webui/system/restart` 重启，两个插件数据库共 33 表、140,136 字节 BLOB 的完整逻辑摘要保持一致；此检查在群和手动流程之前执行。
- **最终全量冷启动 / PASS**：群和手动流程后，两个数据库共 **33 表、278,990 字节 BLOB** 的 schema、全部行与 BLOB 摘要完全一致，包含授权、预算、单作品锁、群策略及发送回执；没有新增模型或绘图调用。四个空间的最终只读 HTTP 复核也保持全库不变，详见 `final-verification-v2.json`。
- **收尾 / PASS**：在线确认自主创作关闭，持久撤权与执行限额关闭已生效，再只结束本次 Windows Job 所有进程。所属 PID 全部退出；即时端口探测有一次过渡态，随后 `post-shutdown.json` 的三轮稳定探测均无监听，三个端口均可独占重绑。原测试数据保留，未宣称通过强制结束进程证明了优雅退出。
- 对已安装包的 RECORD 重算 SHA-256：MaiBot 788 项、SDK 79 项、Dashboard 228 项，共 **1,095 项全部相符**。范围为带 SHA-256 且在 site-packages 内的条目，不包含运行数据及包外入口。
- 上轮缺少公开来源而跳过的 **27 个不同外部契约案例已全部补齐通过**；包含独立 MCP HTTP、原生 IPC 模拟 CLI、请求恢复及 SnowLuma/Host/SDK 超时契约。它们属于契约和故障替身测试，不等于 QQ 或已安装 Host 的定向丢包验收。原有 20 项 Windows 链接权限跳过仍保留。
- CSS 修改后的发行白名单和 Studio Host/页面契约共 **13 个不同案例通过**。原生 IPC 两个参数案例在测试依赖诊断修正后再次通过，属于前述 27 项，不重复加总。
- 最终文档与白名单调整后，统一检查入口的静态错误检查、包边界与真实 Host Loader 共 **5 项通过**；其中 2 项包测试与上述 13 项重叠，不能累计相加。
- 独立只读审查核对了候选 ZIP、45 个 Python 文件不变、CSS 修复、测试脚本断言、手动与群接收证据及数据库摘要。浏览器由单独指定的 `gpt-6.1-sol / high` 执行；这些都不代表用户人工验收。

## 发现与修正

1. **窄屏详情溢出**：作品编号包含连续哈希，版本与评审筛选行将 iframe 撑到 604px。为 `#filter` 增加 `overflow-wrap:anywhere`，保留完整编号和原查询行为；修复后滚动宽等于可用视口宽，无横向溢出。
2. **外部测试缺依赖误报超时**：原生编辑 IPC 测试还依赖服务仓库的 `tests/fake_codex.py`。仅提供 `src/` 时原先会等待并表现为编辑超时；现在明确报告缺少模拟 CLI，开发文档说明完整依赖。
3. **文档版本落后**：工作区文档的 schema 9 / 1..9 更正为 schema 10 / 1..10。

首轮控制器在创作及 HTTP 检查完成后，因补充模块尚未写好而终止；同一状态继续验证，没有重放已有绘图。原始 FAIL 文件保留。早期外部契约运行因缺少模拟 CLI、Host 或 SDK 来源出现失败／跳过，也保留原件；最终按测试身份合并成功证据，不删除失败记录或把跳过改写成通过。

首次终态对账还识别出控制器只等配置读回、未等待 Runner 异步应用就停机的问题。下一次启动按已关闭的配置补做 4 次撤权和全局执行限额归零。`shutdown-transition.json` 通过只读、内存逆还原重算摘要，精确证明仅这 3 张表发生预期变更，其余 30 表和全部 BLOB 未变，已用额度和发送记录未清空。控制器已改为等待实际持久状态收敛，再执行上面的 v2 全库对账。首轮 `final-verification.json` 的 FAIL 保留，不冒称该次前后完全相同。

首次浏览器导航到 Host 的 `/plugins` 实际打开市场，目录读取尝试被 DNS 守卫阻断；后续使用 `/plugin-config` 和 Studio。带调用栈的新记录定位到 Host 的 `git_source.py` / 来源目录加载。守卫为 Python 审计与 Windows ConnectEx 包装，不宣称等价于 OS 防火墙。测试实例起初沿用净化后的旧合成模板，并未读取生产配置；准备脚本现改为从已安装包公开配置类生成模板，单独生成检查通过，未将新方法冒称为首轮配置来源。

## 未覆盖范围

- 真实 Codex 登录、订阅限额、真实图像质量、QQ 适配器上传与实际 QQ 收图，以及用户人工验收。
- 已安装 Host 链路中，MCP 持久接单后定向丢 HTTP 回执、Host 已发送后定向丢 Host→Runner IPC 回执。相关未知状态和禁止重试规则有独立契约／离线回归证据，本轮未把正常重启等同于故障注入。
- 群 Planner 构思工具的非空记录、群原话采集、同一群分享策略翻转。收藏场景的模型遵循 `sharing.allowed` 而等待，未在本轮测试中强行要求分享来验证拒绝路径。
- 群单作品同时受 `render=2`、`share=1` 的普通预算限制；本轮计数不能独立证明普通预算仍有余量、跨日或换委托人时的永久限制。
- 群浏览器窄屏与详情／原图因隔离浏览器断连未继续检查；私聊对应窄屏路径已完成，但不替代群页面实测。Studio 没有独立的暂停状态字段，暂停行为由真实消息与账本测试证明。
- 本轮只用合成 schema 10 状态冷重启，历史 schema 迁移沿用上轮独立测试；本轮图片较小，HTTP 原图读取未覆盖真实多块大图。
