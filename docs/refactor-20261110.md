## 已实现的职责边界

| 原集中点 | 当前划分 | 保留的边界 |
| --- | --- | --- |
| Artist 的回执、评审、分享 | `contracts`、`receipts`、`reviewing`、`sharing` | Artist 协调状态；组件接收所需能力，不持有整个 Artist |
| Store 的 schema、连接、评审和唤醒 | `schema`、`sqlite_uow`、`ledger_repository`、`review_repository`、`wake_repository` | 同一连接、同一事务、稳定业务门面；授权和预算不拆库 |
| 手动/自主投递 | `host/delivery_runtime.py` | 同一原子发送意图；派发前失败与派发后未知分别处理 |
| 命令与配置生命周期 | `host/runtime_generation.py` | 配置、客户端和发送库属于同代，长网络调用不占用全局锁 |
| 私有辅助方法跨层复用 | 公开协议契约、`async_work`、`image_validation` | 稳定标识、错误码和旧导出兼容；核心图片校验不依赖 Host |
| 分块图片展示 | `workspace/images.py` 有界缓存 | 每次仍校验当前权限、原始字节摘要；最多保留四个解码结果 |

重构前 Store 为 3,033 行，Artist 为 947 行。职责拆分后约为 2,100 行和 601 行；主要收益是隔离事务与外部效果，而非单纯减少总行数。Store 中跨领域立项、预算、素材和档案编排仍需明确维护，不宣称所有复杂性已消除。中文注释主要解释授权复核、事务所有权、取消收尾、恢复与缓存边界。

## 测试整理原则

原有 2,796 个收集用例保留。共享数据、fixture、模拟器与公开 Host 装载器移入 `tests/support`，测试模块之间不再互相导入；回归按业务场景保留在原文件。测试数量不是删减目标，重复准备代码与测试入口才是本轮整合重点。

根 `scripts/check.py` 统一所选 Ruff 错误规则与 pytest，提供 `all/unit/local/external` 四种选择。可直接运行 pytest，标记与 suite 选择组合生效。外部测试缺来源会明确跳过；`--require-external` 可让未执行的外部契约导致非零退出。历史迁移改用 v7 固定 DDL；固定 Host 目录输入需通过指纹核验；版本断言读取 manifest、pyproject 与配置示例，旧配置输入保持原值。
