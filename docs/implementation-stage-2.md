# 小画师阶段 2 模拟创作运行器

阶段 2 将阶段 1 的持久底座接成统一创作流程：聊天与无人时段唤醒、灵感、计划、评审、版本和独立分享决策。`Artist` 必须显式注入思考回调、模拟绘图与模拟发送；没有默认网络客户端，绘图或发送后端未声明 `simulation=True` 时拒绝启动。

本阶段不改 MaiBot 本体或 MCP，不部署，不调用真实模型、绘图或发送。`plugin.py` 不自动创建运行器或挂接 Host Hook，现有命令路径保持原样。这里验证的是可注入模拟事件的插件运行组件，不是已经启用的聊天机器人。真实 Host 事件适配、视觉模型效果和后续 MCP 接口仍须单独验证。

## 模块和调用方式

| 模块 | 已实现内容 |
| --- | --- |
| artist.py | 异步统一推进器，所有 SQLite 调用经过工作线程；模型、绘图和发送调用均有超时边界 |
| thinking.py | 注入异步模型回调，严格校验灵感、计划和评审结构；只返回建议，不执行外部工具 |
| store.py | schema 2：持久唤醒、领取水位、退避、灵感、计划、不可变图片版本与评审 |
| policy.py | 沿用阶段 1 的授权、预算、幂等和未决操作约束 |

可信调用方先使用阶段 1 API 建立空间、持续授权和预算，再显式构造 `Artist(store, space_id, scope, Thinking(callback), renderer, sender)`。Scope 必须来自已核实的 Host 归属，不能从模型输出构造。

- `on_chat(message_id=..., text=...)` 保存真实消息事件，重复同消息不重复唤醒，同编号不同内容拒绝；不直接绘图。
- `tick()` 检查持久定时点，再运行至多一个批次；无人聊天也走同一入口。
- `run_once()` 领取待处理事件并推进一次流程，可用于事件驱动或测试。
- `on_completion(request_id=...)` 只唤醒已登记操作，不相信通知携带的完成状态。
- `serve(stop_event)` 是显式启用的定时循环，插件导入和加载不会启动它；调用方负责生命周期和异常处理。
- `recover(offline=True)` 仅在旧推进者停止后使用，释放遗留领取权并将未决外部调用保守标为未知，不重放调用。

## 统一唤醒与灵感

领取权在数据库事务中仲裁，同空间不同运行器或连接不能同时推进。每批最多 64 条，结束只确认领取时的水位，期间到达的新事件与剩余积压留给后续批次。定时点按当前时间推进，不补跑停机期间所有错过的时刻。

模型或预算处理失败后，事件保留并持久退避 300 秒，避免热循环重试。已明确失败的思考可以在后续批次重新尝试；状态未知的思考或绘图不能直接重放。等待决策也会暂停后续领取，恢复时间持久保存。

思考调用本地超时、连接错误或回调明确报告 `THINKING_UNKNOWN` 时保留 unknown 与预算占用，同一批次重开和跨日均不重放。明确失败与无效建议才按已消耗的失败尝试记录。在途绘图的只读对账优先于可选的新聊天灵感提取，因此思考额度耗尽不会挡住原任务结果落库；未处理聊天仍保留，额度恢复后继续积累。

新聊天在已有绘图或评审期间仅调用 `inspire` 积累灵感，不覆盖已有计划。其他时候 `plan` 同时提取灵感并提出下一步。聊天来源只能引用本批真实事件，自主主题用空来源列表并标记 idle，不编造生活经历。灵感按来源类别与规范化摘要去重、合并真实来源、设置有效期，每空间至多 100 条；同一主题的聊天和自主来源分别保留，已消费的灵感不再提供给新计划。

原始事件文本最多 4096 字符，消息/来源编号最多 200 字符。模型上下文仅含公开人格、限定事件、最多 50 条灵感、当前活动作品和最近 20 条已结束作品，不携带 scope、凭据或任意发送目标。数据库保留处理及幂等证据，不作为跨空间共享记忆。

## 创作和评审

`plan` 支持 create、continue、wait、defer、abandon、share。创建计划必须写明意图、主体、气氛、绘图描述与完成标准；再次唤醒时仍由模型决定继续、休息、延期或放弃，定时到达不等于必须绘图。模型建议在记为成功前检查行动与作品状态是否匹配，非法建议按思考失败退避，避免持久缓存卡住后续合法决策。

一个空间至多一份未结束计划。绘图前持久预留稳定请求和冻结参数，再次复核授权版本与当前预算。思考返回前发生撤权或重新授权时，旧建议不用于新的创作操作；额度收紧作用于已有计划。

模拟绘图结果包含请求编号、内容摘要、原任务编号、任务状态和可选图片。编号、摘要或任务绑定不匹配时保持未知，不绑定无关结果。丢失提交回执仅按原编号查询；未找到不重提。损坏产物只从原任务恢复，不重新绘图。

图片入库前校验 MIME、大小和 SHA256；版本与父版本不可改写，评审、分享及细化前再次核对已保存图片的摘要。评审回调接收真实图片 bytes 和 MIME，而非仅接收绘图描述。模拟评审只验证数据路径和行为规则，不证明视觉模型理解或艺术评价质量。

评审结果为 accept、revise 或 discard。revise 必须说明问题、具体修改要求和保留内容；新版本引用原图数据，同一作品累计修订上限，达到上限保留最佳版本结束。模型可明确选择旧版本为最佳版本。模拟后端不支持编辑时保持阻塞，不降级为文字重画。

可用图片与执行结果分开记录：图已保存但回合未知时，可以评审，不能启动下一轮修订。先对账原操作，再应用已保存的评审，避免重复评价或额外绘图。评审调用失败保留 review_pending 和原图，退避后恢复，不记录成差评。

## 分享和恢复

接受作品只将其标为 finished，不自动发送。后续 plan 必须单独选择 share，目标固定为来源空间。分享意图先落库，实际使用阶段 1 的原任务归属与旧发送锁检查。

同一版本重复分享决策只返回原记录。发送回执丢失、超时或类型异常进入 unknown，重启后不自动重发。所有后端均为显式模拟对象；真实发送适配和发布策略的完整上线验证属于后续阶段。

## 数据库升级与兼容

显式打开 ArtistStore 时，schema 1 在单个事务内新增 schema 2 表并更新版本；旧空间、授权、预算、操作与 legacy 锁保留，普通打开不恢复在途调用。未知或更高版本继续拒绝加载，不能用旧程序强行打开 schema 2。

本轮升级测试仅使用临时合成数据库。未来对真实库升级前须停止写入者、制作完整备份并确认回滚入口；本阶段没有加载或迁移真实数据库。

## 验证入口

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
& ./.venv/Scripts/python.exe -m pytest -p no:cacheprovider tests/test_artist_flow.py tests/test_artist_state.py tests/test_thinking.py -q --basetemp=dist/validation/artist-stage2-new-run
& ./.venv/Scripts/python.exe -m ruff check --select E4,E7,E9,F plugin.py bridge.py delivery.py policy.py store.py artist.py thinking.py scripts/build_bundle.py tests
```

basetemp 必须是新的隔离目录；不要指向现有任务、发送库或实际服务 state。测试覆盖聊天/定时统一流程、迟到事件、多连接领取、延期与放弃、额度收紧、授权变化、评审失败、原图输入、版本选择、修订上限、不支持编辑、未知提交、原图损坏、取消、未知发送与跨停机定时恢复。
