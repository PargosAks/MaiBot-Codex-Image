# 插件排错

适用于插件 **0.8.0** 连接已有 MCP **0.5.0**。保留原任务编号和发送记录，避免重复提交。不要公开 config、secret、登录文件或完整私密日志。

## 升级后找不到服务入口

先核对旧服务是否从本仓库 `service/` 运行。0.7.0 移除了服务目录及部署脚本，不能在仍承担服务入口的旧仓库原地更新。保留旧完整仓库给服务，新插件部署到独立目录；保留 Host 插件身份、原 `data_dir`、config、secret 和完整 `state`，见 [升级指南](quickstart.md)。

若入口已被删除，由维护者先确认进程和原配置引用；不要另起共用同一 `state` 的服务，也不清理任务、锁或发送库。原服务资料见 [固定提交部署文档](https://github.com/PargosAks/MaiBot-Codex-Image/blob/e50a7b6f0e090d6a5053ac00d4f0b14e92aee272/docs/host-service.md)，恢复操作另行核实。本仓库没有可重跑的 setup 或宿主机安装命令。

## 命令未触发或提示未授权

核对实际插件加载路径、`plugin.enabled`、`connection.allowed_users` 和用户真实身份。名单用英文冒号 `platform:user_id`，空列表拒绝所有人。

另需授予用户 `codex_image_command` 权限及插件 `send.text` / `send.image` 能力。保存后重载插件，不会启动 MCP。诊断也受用户身份及授权限制，不能由未授权用户验证连接。

## MCP 连接超时或拒绝

1. 从 MaiBot 实际运行环境检查 URL 和 `/mcp` 入口；Docker bridge 内 localhost 指向容器自身，宿主机成功不能证明容器可达。
2. 核对监听、实际容器路由、防火墙及 MCP 允许的 Host；网关和宿主机别名按环境确认。
3. 核对原密钥一致且至少 32 字符、两端时间与 MCP 0.5.0 签名兼容性，不将密钥粘贴到 URL 或日志。
4. URL 不能带凭据、查询或 fragment。Bridge 不继承环境代理且不跟随重定向；裸 HTTP 成功不等于 MCP 会话成功。

不要禁用鉴权或暴露无保护公网端口。服务进程、Codex 登录和部署问题交由独立服务维护者处理；诊断不证明登录或绘图有效。

## 等待超时或任务结果未知

`watch_seconds` 到期只停止自动等待，不取消服务任务。用 `/画图状态 原任务编号` 查询，成功后按发送记录规则用 `/重发画图 原任务编号` 取原图。`failed/outcome_unknown` 不会自动重画，不要直接重复 `/画图`。

归属由 Host 平台、用户及聊天流决定；跨用户或换聊天查询被拒绝时，不改签名或复制编号绕过。

## 图片已生成但未收到

分别核对产物、Host 发送能力、插件发送记录与聊天端。明确的权限拒绝可记录为已知失败，外部发送异常可能为未知结果，不能都当作可重试失败。

### QQ 慢上传与发送回执超时

`connection.send_timeout_seconds` 独立控制图片发送 RPC 的等待，默认 **240.0 秒**，允许大于 0、至多 600 秒；自主分享外层额外保留 5 秒供结果落盘。`autonomy.timeout_seconds` 仍用于模型及其他操作，`connection.watch_seconds` 用于等候绘图任务，两者均不能替代发送等待。

2026-11-01 的实际上传耗时 156881 ms，QQ 最终送达，但 30 秒时等待已结束。源码定位发现多个独立的超时：

| 层级 | 原限制 | 本轮处理 |
| --- | --- | --- |
| Snowluma adapter OneBot 动作 | `client.action_timeout_sec = 30.0` | 公开配置，可调整；变更会重连适配器 |
| MaiBot Platform IO → 网关组件 | 未声明 `timeout_ms` 时默认 60000 ms | 须由网关元数据声明更长等待，不能仅延长外层 |
| 绘图插件 → Host 能力 RPC | 未显式指定时默认 30000 ms | 显式传递 `send_timeout_seconds × 1000`，向上取整 |
| 自主分享外层 | 与模型等待共用 | 独立使用发送等待 + 5 秒 |

候选链路预算为动作 **210 秒**、网关 **230 秒**、插件 RPC **240 秒**、自主分享外层 **245 秒**。此数值覆盖已观察的 157 秒上传，并非保证所有上传都能在期限内完成。仅更新绘图插件不能修复适配器和网关的短等待；应用前须核对目标版本的声明方式、当前在途操作和实际配置，保留旧配置以便回退。禁止修改运行中的已安装 MaiBot 包来绕过限制。

已核实 VPS 的 Snowluma adapter 1.1.9：`plugin.py` 的 `@MessageGateway(name=SNOWLUMA_GATEWAY_NAME, ...)` 未声明超时，可在其 `protocol="snowluma"` 后增加 `timeout_ms=230000`；现有 SDK 会将此元数据交给 Host driver，无需修改 MaiBot 本体。同时将该适配器的 `[client] action_timeout_sec` 配为 `210.0`。这是适配器源代码及配置的两处配套修改，不会由绘图插件自动写入；重载适配器后才会重新注册网关。适配器更新可能覆盖此声明，升级时须复核。应用和回退均应避开在途发送，仅恢复对应源码行和配置值，不恢复或覆盖发送数据库。

手动取图命令声明 720 秒组件等待，容纳最大 600 秒图片发送及 MCP 取图、末尾提示；具体图片 RPC 仍按配置到期。自动取图在产物就绪后退出绘图等待计时器，再进入独立的发送等待。

2026-11-02 已在所维护 VPS 应用上述适配器 1.1.9 配套修改并重载插件。适配器修改后的 `plugin.py` SHA256 为 `b6fa5363d848f40e72cf982cfb05e05c731e80681ec8ac1b1c4116d85fd48dd7`。此处仅记录该安装实例，不代表上游适配器已包含修复，也不代表其他安装会自动获得设置。版本升级后重新核对，避免恢复成 30/60 秒短等待。

即使用户已确认收图，原 `send_unknown` 及自主创作 `unknown` 记录仍保留，不自动改成成功，不自动或手动重发。超时、取消、回执丢失后的晚到结果不会解除已有锁；本轮修改只影响未来被正常授权的发送。

`sent/send_failed` 可按手动路径发送原图；`sending/send_unknown` 自动和手动均禁止重发。先核对真实聊天结果，不清空 `delivery.sqlite3`、不新建 Host 数据目录解除保护，也不重新生成替代原任务。

## 验证边界

连接、状态、图片返回、Host 接收与实际聊天收图分别记录。模拟测试、历史结果和进程健康不能替代当前真实流程验证，见 [validation.md](validation.md)。

自主创作默认关闭；如需了解持续委托、预算、Host 能力、模型任务和失败恢复，见 [阶段 6](implementation-stage-6.md)。MCP 0.5.0 的命令兼容性不等于具备自主创作所需的 `lookup_v1` / `edit_v1`。
