# 插件排错

适用于插件 **0.7.0** 连接已有 MCP **0.5.0**。保留原任务编号和发送记录，避免重复提交。不要公开 config、secret、登录文件或完整私密日志。

## 升级后找不到服务入口

先核对旧服务是否从本仓库 `service/` 运行。0.7.0 移除了服务目录及部署脚本，不能在仍承担服务入口的旧仓库原地更新。保留旧完整仓库给服务，新插件部署到独立目录；保留 Host 插件身份、原 `data_dir`、config、secret 和完整 `state`，见 [升级指南](quickstart.md)。

若入口已被删除，由维护者先确认进程和原配置引用；不要另起共用同一 `state` 的服务，也不清理任务、锁或发送库。原服务资料见 [固定提交部署文档](https://github.com/PargosAks/MaiBot-Codex-Image/blob/e50a7b6f0e090d6a5053ac00d4f0b14e92aee272/docs/host-service.md)，恢复操作另行核实。本仓库没有可重跑的 setup 或宿主机安装命令。

## 命令未触发或提示未授权

核对实际插件加载路径、`plugin.enabled`、`connection.allowed_users` 和用户真实身份。名单用英文冒号 `platform:user_id`，空列表拒绝所有人。

另需授予用户 `codex_image_command` 权限及插件 `send.text` / `send.image` 能力。保存后重载插件，不会启动 MCP。诊断也受用户身份及授权限制，不能由未授权用户验证连接。

## MCP 连接超时或拒绝

1. 从 MaiBot 实际运行环境检查 URL 和 `/mcp` 入口；Docker bridge 内 localhost 指向容器自身，宿主机成功不能证明容器可达。
2. 核对监听、实际容器路由、防火墙及 MCP 允许的 Host；网关和宿主机别名按环境确认。
3. 核对原密钥一致且至少 32 字符、两端时间与 MCP 0.5.0 签名兼容性，不将密钥粘贴到 URL 或日志。
4. URL 不能带凭据、查询或 fragment。Bridge 不继承环境代理且不跟随重定向；裸 HTTP 成功不等于 MCP 会话成功。

不要禁用鉴权或暴露无保护公网端口。服务进程、Codex 登录和部署问题交由独立服务维护者处理；诊断不证明登录或绘图有效。

## 等待超时或任务结果未知

`watch_seconds` 到期只停止自动等待，不取消服务任务。用 `/画图状态 原任务编号` 查询，成功后按发送记录规则用 `/重发画图 原任务编号` 取原图。`failed/outcome_unknown` 不会自动重画，不要直接重复 `/画图`。

归属由 Host 平台、用户及聊天流决定；跨用户或换聊天查询被拒绝时，不改签名或复制编号绕过。

## 图片已生成但未收到

分别核对产物、Host 发送能力、插件发送记录与聊天端。明确的权限拒绝可记录为已知失败，外部发送异常可能为未知结果，不能都当作可重试失败。

`sent/send_failed` 可按手动路径发送原图；`sending/send_unknown` 自动和手动均禁止重发。先核对真实聊天结果，不清空 `delivery.sqlite3`、不新建 Host 数据目录解除保护，也不重新生成替代原任务。

## 验证边界

连接、状态、图片返回、Host 接收与实际聊天收图分别记录。模拟测试、历史结果和进程健康不能替代当前真实流程验证，见 [validation.md](validation.md)。
