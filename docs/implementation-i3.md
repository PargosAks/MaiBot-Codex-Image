# I3 素材目录与分层上下文

素材入库是独立的创作建议，不自动分享，也不重新绘图。只有持有有效图片评审接受证据的版本可以入库；作品 finished 或 best_version 指针本身不够。

## 状态和模型接口

`archive` 指定已完成作品、用途、标签和原因。插件查明其已认可的最佳版本，冻结来源与评审摘要，按空间及版本确定素材 ID；相同请求重复执行返回原记录，改变不可变参数会拒绝。`inspect_assets` 选择最多三项详情。`create.references` 仅接受可见素材的 `{asset_id,role,reason}`，角色为 character、style、composition、palette。

概要最多八项，详情最多三项且序列化文本不超过 6000 字符。查询按文字与标签确定性筛选，不调用模型。素材摘要来自成功的原始评审，明确标记“评审理由／优点”，不把生成提示词描述成实际看图结论。

每个计划冻结来源版本、SHA256、MIME、选择理由、用途和摘要。I3 的 usage 为 `text_context`，提示词明确说明“仅文字灵感，未输入参考图”；实际图片参考属于 I5 的显式协议。新图与编辑使用同一冻结引用，后续目录变化不修改旧计划。

## 存储、配额和迁移

schema 5 在原 SQLite 内追加 asset_catalog 与 asset_selection。每空间最多 100 项、累计图片长度最多 64 MiB；停用素材仍占配额，不删除作品或审计字节。素材去重不授予跨空间访问权，撤权阻止新的入库、选择和计划，历史仍可读。

旧计划没有 references 时行为不变；已有版本、发送记录、未知操作和预算不会重置。素材停用后不进入新计划，已冻结引用仍可追溯。

## 验证

`tests/test_assets_store.py` 检查迁移、配额、来源证据、幂等、隔离和冻结；`tests/test_assets_flow.py` 检查完成但未分享的作品入库、详情选择、文字复用和未认可版本拒绝入库。均使用合成模型、图片字节和发送器，不代表真实审美验收。
