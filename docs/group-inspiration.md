# 群灵感簿：从群聊到自主创作

一个群对应一个创作空间。成员提供见闻，不授予操作权限；持续委托人负责授权和限额，MaiBot 决定是否创作。例如“今晚雨好大”和“便利店还亮着灯”可以合为“雨夜里的便利店”。没有人发起绘画任务，小画师也可以留意这个场景，或者不采用。

## 行为和权限

- 管理员逐群开启“MaiBot 记下创作念头”。开关默认关闭，升级不自动开启，也不把群成员加入白名单。目标来自 Host 的真实群规划会话及已验证配置；一个群或会话存在多个空间归属时拒绝记录。
- 用户已确认：记录的是 MaiBot 对群聊形成的视觉构思，不是逐条成员发言。不扫描历史或监控接口，不从昵称或模型提示文本还原账号，不声称知道是谁贡献了几条消息。模型自己选择记录或继续聊天；不保证覆盖每条群消息。
- 每群独立持久去重与限频。保存受控标签生成的主题、时间及“MaiBot 群聊构思”来源；不存自由文字、聊天逐句摘录、成员账号。阶段 2 将授权念头交给同群创作运行器规划；旧实验记录与新念头分开存储和展示。
- 工作区只供有权限的管理员查看。念头归属不能通过模型参数改到其他群；原作品、档案和参考图的权限不变。记灵感不在群里逐条确认，不自动创建绘画任务。

## 实施顺序

1. **群灵感簿**：核实过滤边界，改用已有规划生成的自主念头，通过纯插件接口保存和只读展示。模拟多成员话题合成、两群隔离、重复规划、工具直接调用、撤权与重载。该阶段只保存；工具选择后 Host 可能继续正常规划回合，不能承诺总模型用量完全不变。
2. **自主采用**：把未采用主题交给原有聊天和无人时段规划流程。模型可以等待或选择念头立项，再沿用创作、评审、细化、弃稿和收藏流程。采用时关联来源主题，重试不重复立项；模型调用纳入原有空间和全局预算。
3. **独立收集和分享策略（已实现）**：新增“仅收藏／允许分享到原群”策略，将念头记录及采用与分享许可拆开。评审通过仍不等于必须分享，允许分享后由 MaiBot 决定是否分享；新群和升级后的旧群均默认仅收藏，原群自主分享需管理员显式配置。2026-11-04 已完成本地 Host 模拟链路和 VPS 部署验证；未做真实群绘图或 QQ 群收图验收，见[验收记录](group-inspiration-validation.md)。

**硬约束：不修改 MaiBot 本体或 MCP。** 新念头功能不依赖逐条过滤凭据。早期严格消息采集器只保留隔离测试入口，不能以未过滤消息替代凭据。

**实施约束：不改 MaiBot 本体。** 不新增 Host 事件，不打补丁、不挂钩内部收信函数，不读取 Host 数据库或绕用 Dashboard 管理员监控。之前设计的最终凭据仅用于严格逐条来源的隔离测试，不作为生产实现前提。

## 纯插件接入方案：让 MaiBot 自己记下念头

在现有群规划回合提供可选插件工具 `codex_image_remember_thought`（使用当前 SDK 的 Tool 注册）。比如有人聊到夜雨、另一人聊到便利店，MaiBot 可以记下“雨夜的便利店灯光”，也可以继续聊天。无需 @、命令、逐句转存或插件为记念头另行发起模型请求。只有 Host 既有 planner 所见的话题可能启发念头；未进入规划的发言不保证被采用。阶段 2 将这些念头提供给原有聊天和无人时段创作规划。

- **只保存自己的构思。** 工具仅提供受限视觉标签和本轮上下文令牌两个参数，不接受账号、群号、消息号或原文。工作区来源为“MaiBot 群聊构思”，显示主题和时间，不显示贡献人数或消息数。当前题材词表有限，不能表达任意人物、角色或故事；不匹配标签时可以选择不记录。
- **限定目标和效果。** 使用真实规划上下文的会话，与管理员已授权的群空间及 Host 群流再次核对。模型不能通过指定群改变归属；若不能确认调用来自当前授权群规划回合，直接拒绝。应用去重、限频；记灵感可以提示同群运行器规划，不能直接绘图或增加分享权限。采用主题、绘图、分享分别由原创作决策控制。
- **身份取自 Hook。** `before_request` 仅在 Host 已选中该工具时，核验当前授权群并为本轮提供短效令牌；不会重新加入被 Host 禁用的工具。`after_response` 按可信会话、令牌和结构化函数调用保存被选中的念头。群号不从模型参数或聊天文本推断；直接调用工具只能取本轮最小回执，没有写入路径。Hook 保存的是规划选择，未必代表后续工具执行已完成。
- **为什么不从查询补来源。** 固定 Host 的模拟反例：一条带首尾空格的精确匹配命令，候选判断使用去空格文本，执行时使用原文。它能跳过禁词和正则检查、最终以 `is_command=False` 进入普通存储。因此即便逐项吻合群、消息号、成员和 Host 接收时间，也不能将查询结果认作过滤回执。小画师写自己的想法无须推断那条回执。

## 当前模块、持久化与回退

- `group_thought_runtime.py` 对接两个现有 Hook 和只读工具回执。每群最多保留一个待确认规划，120 秒过期；新回合替代旧令牌。配置更换、撤权、关停后拒绝旧回调；有在途 SQLite 写入时等待其结束再关闭，已写入的历史不回滚或删除。
- `group_thoughts.py` 维护独立 `group_thoughts.sqlite3`。新令牌请求幂等；相同主题共用一条记录；每群最多每 600 秒记录或更新一次。默认上限 128 个主题、10,000 条请求回执，满时停止接纳新请求，不自动删旧记录。到容量上限的清理/归档策略不在本阶段内。
- 工作区选择群空间 → **创作念头**，查看主题、来源、首末时间、采用状态及关联作品。**已采用表示已经建立创作计划，不代表生成或分享成功**；未导入或尚未被选择的念头均为“未采用”。只读查询不创建数据库、不迁移账本、不冲刷数据、不触发模型或工作。关闭配置保留记录供原绑定管理员检查。
- 不新增 Host capabilities，不用旧 `ON_MESSAGE` 枚举，不接管收信过滤，不访问 MaiBot 数据库或 Dashboard WebSocket，不依赖本体热补丁。已固定验证 Host `062d45cf`；其它版本需按相同契约验证。

## 阶段 2：同一创作流程自主采用

若群空间已在阶段 1 开启 `group_inspiration`，升级到阶段 2 后，历史未采用念头也会进入原授权的规划候选；该开关不再只控制保存。需要暂缓采用时关闭它，已有计划不受影响。阶段 3 新增的“仅收藏”限制分享，仍允许有授权的规划、生成与评审，不表示只记录而永不绘图。

`GroupThoughtRuntime` 读取经过原绑定核验的受控自我念头，送入同群 Actor 的规划上下文。`inspirations` 中的来源为 `origin="group_thought"`，保留稳定念头编号；不伪装成委托人的聊天事件，不补造群成员身份或贡献统计。私聊或其他群的 Actor 不能看到这些候选。

1. **可见和等待。** 聊天唤醒、无人时段唤醒与新念头提示沿用同一个 Actor。模型可以 `wait`，也可以选择当前可见念头的 `inspiration_keys` 执行 `create`，自行决定构图、主题和完成标准。仅导入或查看念头不算采用；模型思考沿用原空间与全局预算，不为每条成员消息另开绘图流程。
2. **采用和计划。** `artist.sqlite3` schema 8 新增 `group_thought_policy` 保存 scope、群绑定、启用状态与授权版本；`group_thought_links` 保存稳定 `note_id`、`inspiration_key`、摘要、群号以及 `adopted_by/adopted_at`。`plan_work` 在建立计划的同一事务中写入采用关联，失败一起回滚。来源库仍独立保存历史；不在两个数据库间分别写“采用成功”。同一念头重复记录或重启恢复都不能再次自动采用，既有作品和发送结果未知锁继续保留。
3. **继续和细化。** 新候选不覆盖正在进行的作品或冻结的 brief。已有计划按原流程继续、延后或放弃；生成后由原 review 判断接收、弃稿或细化，最多执行原授权允许的细化次数。细化继续使用原图和版本关系，不能凭念头绕过预算、能力或源图校验。
4. **分享和关停。** 分享沿用原授权、目标绑定、预算和发送记录；记录念头或采用不产生额外分享许可。`group_inspiration=false` 后屏蔽新记录和新采用，保留已经建立的计划和历史关联；停止整个自主创作仍使用原总开关。阶段 3 再按独立分享策略限制群内自主分享。
5. **只读投影。** Studio 兼容 artist schema 1..9；旧 1..7 没有采用链接时显示“未采用”。schema 8 起只关联同 `space_id`、同 `note_id`、同完整 scope 与群绑定的链接及作品，不按全局念头号或作品号跨群联表。页面展示采用状态和关联作品的最小投影，继续使用现有私有 `studio_records` 契约，没有写操作。

阶段 2 的验证使用临时 SQLite、受控模型决定、模拟绘图和模拟发送，覆盖聊天与无人时段选择、等待不采用、保留已有 work、原图细化、重启防重、关闭开关与跨群隔离。Studio 测试另核对真正立项前后的状态、旧 schema 读取、完整绑定错配，以及文件摘要和 SQL 无写入；实际 QQ 收图与线上运行需另行部署验收。

## 阶段 3：独立控制群内自主分享

群空间有两个独立配置：

| 配置 | 取值及作用 |
| --- | --- |
| `autonomy.spaces[].group_inspiration` | 默认 `false`；开启后允许 MaiBot 记录群创作念头，并提供给原群规划自主采用 |
| `autonomy.spaces[].group_share_mode` | 默认 `"collect_only"`（仅收藏）；显式设为 `"original_group"` 后，允许 MaiBot 自主决定是否向已绑定原群分享 |

“仅收藏”作用于整个群空间的自主分享，包括委托人聊天、无人时段和群创作念头产生的作品。它不阻止原授权内的规划、生成、评审、细化或保留作品，也不会给群成员操作权。`group_inspiration=false` 不自动撤销已经成稿作品的原群分享许可；已有作品是否可分享由独立模式、原委托、预算和发送历史共同决定。私聊继续使用原有授权行为，不受群分享模式影响。手动命令及手动发送仍按原有身份、能力和发送记录规则授权，群模式不会额外授予或取消手动操作权限；`sending/send_unknown` 在手动路径同样不可重发。

`original_group` 只是许可，不是发送指令；MaiBot 可以继续收藏、等待或放弃分享。允许分享也不能把作品发往另一群或私聊。工作区“自主分享权限”显示“仅收藏／可自主分享到原群／私聊原授权”；当前许可状态与真实发送状态分开显示，作品记录中的发送结果仍为准。页面刷新不调用模型、不绘图、不发送，也不把管理员群策略自动带入聊天摘要。

artist 账本由 schema 8 迁移至 9，新增 `group_share_policy`，保存完整归属、群绑定、模式及授权和策略版本，并保存分享认领关联。迁移不改写旧作品、发送意图、累计额度或未知结果。旧群默认拒绝自主分享，不能沿用旧版“已有群就可分享”的推断；管理员需显式设置 `original_group`。只读 Studio 支持 schema 1..9，不迁移旧账本；已知群在 schema 1..8、没有策略或归属不匹配时显示仅收藏。

改变模式不能撤回已发图片，也不能撤回已进入外部发送的请求。在途状态按原回执收敛，`sending/send_unknown` 始终保留并锁定，不能通过切换模式、重载或改额度重发。恢复许可不会清空已耗预算，不自动重新分享旧作品。阶段 3 只在隔离状态库中以模拟绘图和发送验证，线上 QQ 验收需另行授权部署。

## 保留的严格消息采集实验

以下是旧实验路径，仅在注入合成过滤凭据时工作；不用于新念头的生产接入，也不向它伪造成员统计。

1. **认领来源。** `group_ingress.py` 只接受当前启用周期内、最近 120 秒的可信凭据。由管理员配置选择群，原有 Host 流身份检查建立绑定。`group_collection.py` 在读取凭据前后都检查有效委托、白名单、配置与真实绑定；同平台群号或流有多个配置归属时不选取任何一个。配置重载不能沿用旧采集器。
2. **合成主题。** `group_notebook.py` 用本地受控词表识别场景、天气、时段和光色。例如雨夜可以和便利店灯光合并；同群聊到山林和海边则各记各的。无法识别的文字直接略过。这里没有语义模型，不承诺理解任意话题。按整十分钟分窗，每群每窗最多 64 条，每名成员最多 8 条。同一绑定、同一消息号只计一次；相同主题跨窗更新，人数按不同贡献者计数。
3. **保留与丢弃。** 只在独立的 `group_notebook.sqlite3` 中存绑定、主题、计数、时间和群范围内的去重摘要。成员及消息号用带绑定信息的摘要识别贡献，原话和贡献者原始账号不入簿；这不是不可逆匿名的承诺。待合并词条只在内存：关停、撤权或错过窗口结束后的十分钟即丢弃，不用历史回填。已登记的消息号继续防重。默认每群最多 128 个主题、10,000 条去重记录；到上限停止接纳相应新记录，不自动清旧账。真实群开放前应单独确定长期保留与容量策略。
4. **查看。** 在 Dashboard → 小画师工作区 → 选择对应群空间 → 群灵感簿，只读查看主题、人数、消息数、首末时间和是否采用。当前阶段主题均未采用。页面刷新不会建立灵感库、冲刷待合并词条或创建工作。模拟测试显式推进时钟；当前版本不为真实群启动监听或定时器。
